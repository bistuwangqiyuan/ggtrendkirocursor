我们要解决的问题

  • 创业者最大的难题不是“写 BP”，而是“不知道现在该做什么、什么值得做”。
  • 现有 BP 工具（LivePlan / Upmetrics / PrometAI 等）默认“你已有点子”，只负责把点子格式化成文档。
  • 通用 LLM（如 ChatGPT）能写文字，但缺乏实时趋势数据、缺乏机会排序、缺乏结构化财务模型与可交付 PDF。

我们的解法（三段式闭环）

  • ① 热词挖掘：实时谷歌趋势 → AI 去噪归类，沉淀“可线上化机会”的信号底座（复用 Trend Now）。
  • ② AI 商业分析：头脑风暴机会 → 六维评分排序 ROI → 一键生成投资人级 BP（市场/财务/风险，导出 HTML/PDF）。
  • ③ AI 自动建站：把选定机会交给 AI 编程（Claude）自动生成代码并部署上线为可运营网站，人审把关质量；上线数据回流优化前端。

行业背景与趋势

趋势一：生成式 AI 从“写文字”跨越到“写代码、建产品”

多家机构对生成式 AI 2026 年市场规模的测算区间为 US$28.45B（Mordor）至 US$47–55B（Research and Markets / Precedence）， 长期 CAGR 约 28.7%–37%[3]；更广义的 AI 市场 2026 年约 US$539B、到 2033 年达 US$3.5T（CAGR 30.6%）[3a]。 更关键的是，AI 编程（AI coding）已从“补全代码”跃迁到“从自然语言直接生成并部署可运行应用”—— Anthropic Claude（Claude Code）、Cursor 与 Lovable / Vercel v0 / Bolt / Replit 等已证明“描述即产品”的可行性[8]。 随着模型 API 价格持续下探，“AI 写作 + 结构化生成 + 自动建站”的单位成本快速降低，使“从机会直接生成上线产品”在工程与毛利上同时变得可行。

趋势二：趋势数据的实时化与普惠

谷歌趋势（Google Trends）等公开信号让“市场在搜什么”近实时可得。把这些弱信号结构化、去噪、归类为“可线上化的商业机会”， 是过去依赖咨询/调研才能完成的工作，如今可由数据管线 + LLM 编排自动完成——这正是 Trend Now MVP 已验证的能力底座。

趋势三：创客经济与中小企业数字化

全球每年约 5,000 万 家新创企业、存量逾 1.5 亿[4]；仅美国 2024 年新企业申请约 520 万、存量中小企业约 3,480 万[4]。 与此同时，商业计划/规划软件市场约 US$2.6B（2026）、并向 ~US$5B（2035）增长[7]。庞大且持续新增的“要立项、要融资、要规划”的人群，构成稳定需求底盘。

窗口判断。AI 能力足够强（既能写 BP、也能写出可部署的应用）、数据足够易得（趋势实时公开）、成本足够低（token 价格下行）。 现有 AI 建站工具解决“会做”，却默认“你已知道要做什么”；趋势/选品工具解决“发现”，却不交付产品。 把“需求验证（热词）+ 商业分析 + 自动建站”串成一条闭环的整合品类尚无强势主导者——这是一个“天时 + 地利”的进入窗口。

产品与解决方案

Product

一条从需求到产品的三段式商业闭环：① 热词挖掘 → ② AI 商业分析（脑暴 / 评分 / BP）→ ③ AI 编程自动生成并部署服务网站；上线产品的真实数据回流，持续优化前端信号。

核心功能

  • 实时趋势看板：复用 Trend Now，按地区/时间窗/采集时间筛选热词。
  • 机会引擎：将热词聚类为“可线上化商业机会”，给出市场/竞争/可行性初判与六维 ROI 排序。
  • BP 自动撰写：生成执行摘要、市场测算、商业模式、财务三情景与风险，导出 Apple 风格 HTML → 高保真 PDF。
  • AI 自动建站（Claude）：把选定机会的 BP 转为产品需求，由 AI 编程自动生成前后端代码并部署上线，配域名、托管与运营后台。
  • 人审与质量门：自动化测试 + 安全/合规扫描 + 人工抽审，先预览后发布，确保站点可用、可信、合规。
  • 协作与托管：团队共享、版本留痕、模板与品牌定制；生成站点按月托管、可持续迭代（企业版）。

Stage 3：AI 编程自动建站

Auto-Build

把“计划”变成“产品”的关键一跃，也是本平台区别于一切纯 BP 工具与纯建站工具之处：从已验证的机会出发，让 AI 编程把 BP 直接落地为一个可运营、可收款的上线网站。

从机会到上线网站（三步）

①

需求 → 代码

BP 的机会、功能与商业模式被结构化为产品需求规格，交由 AI 编程（Claude Code 等）生成可运行的前后端代码与数据模型。

②

代码 → 上线

自动构建、配置域名与托管、一键部署（复用 Netlify 等），交付一个真实可访问、可收款的网站，而非静态原型。

③

质量与人审

自动化测试 + 安全/合规扫描 + 人工抽审“先预览后发布”；AI 负责大部分体力活，人把关方向与底线。

诚实的能力边界（不夸大）

当前最适合

中小型、标准化的线上服务站、营销/落地页、内容站、轻 SaaS 与工具站——这些正是热词机会最密集的区间。

仍需人工的

高复杂度系统、强合规/支付清算、深度集成场景仍需工程师深度参与；我们以“模板化场景优先 + 人审兜底”控制质量与责任风险（详见第 18 节）。

为何这一步重要：能交付“一个上线运营的网站”而非“一份文档”，把用户从“看完即走”变成“持续托管/迭代”的经常性客户，是激活、留存与客单价的根本跃升，也是闭环数据飞轮的起点。

② 需求验证优先

建站工具从“点子”起步，命中率随机；我们从实时需求信号起步，先验证再建造，显著提升所建产品的存活与变现概率。

③ 已上线 MVP 与流量

Trend Now 提供现成趋势数据与 SEO 流量入口，竞品需从零搭建趋势数据能力。

④ 本地化 + 价格 + 一站交付

原生中文 + 主流价位，且“BP + 建站”一站交付，替代多工具拼接，先吃下被国际工具忽视的中文长尾。

关键假设与方法论

  • 闭环框架：产品 = 热词挖掘（需求验证）→ AI 商业分析（机会/评分/BP）→ AI 编程自动建站并部署，上线数据回流形成飞轮（第 7 节）。
  • 财务自下而上：收入 = 付费用户 × ARPU + 按量/企业；付费用户 = 注册 × 转化率；毛利随 token 降价与缓存提升（55%→75%）。基准按“订阅+按量”保守口径，建站/托管增量列为上行、不计入基准。
  • 种子回报双口径：账面 = 逐年估值 × 净持股 / 成本；风险调整 = Σ(现金退出情景概率 × 现金 MOIC)。
  • 胜率与盈亏比：胜率 = 盈利现金退出概率（28%）；盈亏比 =（平均盈利倍数−1）/（1−平均亏损回收）= 3.64/0.90 ≈ 4.0。
  • 年化口径：成功条件年化 = 平均盈利 MOIC1/5−1 ≈ 36%；风险调整年化 = EV1/5−1 ≈ 6.5%。

创业成功率 / 现金退出率取数与重算说明

区分三个层次并仅以第三层作为收益口径：①存活率（仍在经营，国内三年 76%[1]）；②账面增值（纸面估值，不等于现金）；③现金退出成功率（真正拿到钱）。 以天使被投项目死亡率 31%、IPO 仅 2%、进入下一轮 45%[5] 为锚，叠加“账面存活但无现金退出”的僵尸比例，将盈利现金退出概率定为 28%（较“45% 进入下一轮”更严格、更保守）。 成功退出倍数以国内早期投资退出 IRR 中位数 ~30%[6] 反推，并区分“一般退出 2.5×”与“优异退出 10×”，与幂律分布一致。
